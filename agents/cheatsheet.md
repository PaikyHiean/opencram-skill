# C 子 agent（速查卡）

**何时用**：Phase 9，当要生成 C 速查卡时。orchestrator 按单章派一个 Task 子 agent，
每个只领一章的 `work/distilled/c/in_<k>.json`，控制上下文。

---

## 输入

子 agent 自己读盘（orchestrator 不传全文）：

```
work/distilled/c/in_<k>.json
```

格式：
```json
{
  "chapter_index": 1,
  "chapter_title": "第1章 财产保险概论",
  "slide_count": 45,
  "slides": [
    {
      "anchor": "第一章财产保险概论.ppt#s5",
      "title": "近因原则",
      "paragraphs": [{"text": "近因原则：保险赔偿应基于直接有效地导致损失的原因", "level": 0}],
      "tables": [],
      "notes": "备注：近因需满足三个条件..."
    }
  ]
}
```

---

## 任务

从该章幻灯片（标题 + 正文 + 表格 + 备注）中识别并抽取**以判断/操作为中心的可查用内容**，
按下列四种类型归类：

| 类型 | 代码 | 典型内容 |
|---|---|---|
| 公式/数字门槛 | `formula` | 计算公式、赔付比例、等待期天数、具体数字条件 |
| 规则/条件判断 | `rule` | 承保条件、赔付条件、免责条款（if → then 结构） |
| 对比表 | `table` | 险种对比、条款比较、两种以上并列项目 |
| 流程步骤 | `flow` | 投保流程、理赔流程、核保步骤（有先后顺序） |

**抽取标准（重要）**：
- **以操作/判断为中心**：回答"考试时用来判断或操作的内容"，而非纯定义（定义属于 L2）
- **条件完整**：`rule` 类型必须把所有条件列出，条件不完整的规则不如不列
- **数字优先**：有具体数字（金额/比例/天数）的内容优先收录为 `formula`
- **PPT 原文**：body 内容必须来自 PPT 原文（可精简但不改写）；**禁止 AI 补充**
- **锚点真实**：只使用输入包里的 anchor，不虚构
- **不重复 L2**：纯定义（"X 是指……"）不收，除非定义本身即是判断依据

---

## 产出

写 `work/distilled/c/out_<k>.json`：

```json
{
  "chapter_title": "第1章 财产保险概论",
  "cards": [
    {
      "type": "formula",
      "label": "财产险保费计算",
      "body": "应缴保费 = 保险金额 × 保险费率\n最低保费：50元/笔",
      "anchors": ["第一章财产保险概论.ppt#s12"]
    },
    {
      "type": "rule",
      "label": "近因原则适用条件",
      "body": "① 损失须由直接原因造成，不计远因\n② 若多个原因并发，以主导原因定性\n③ 原因中断或新原因介入时，以最近原因计",
      "anchors": ["第一章财产保险概论.ppt#s5", "第一章财产保险概论.ppt#s6"]
    },
    {
      "type": "table",
      "label": "财产险 vs 责任险",
      "body": "项目 | 财产险 | 责任险\n承保对象 | 有形财产损失 | 法律赔偿责任\n赔款对象 | 被保险人 | 受害第三者\n损失形式 | 直接损失 | 判决赔偿金",
      "anchors": ["第一章财产保险概论.ppt#s18"]
    },
    {
      "type": "flow",
      "label": "财产险理赔流程",
      "body": "① 出险后及时报案（电话/书面）\n② 保险公司派员现场查勘定损\n③ 被保险人提交理赔材料\n④ 保险公司核损审核\n⑤ 符合条件则支付赔款",
      "anchors": ["第一章财产保险概论.ppt#s30"]
    }
  ]
}
```

**字段说明**：
- `type`：`formula` / `rule` / `table` / `flow`（四选一）
- `label`：卡片标题，≤15 字，名词短语（如"理赔申请条件"，不用句子）
- `body`：内容正文，格式约定：
  - `formula`：公式文字，多行用 `\n` 分隔
  - `rule`：条件列表，每条以 `①②③` 或 `条件N：` 开头，`\n` 分隔
  - `table`：**列间用 ` | `（空格-竖线-空格）分隔，行间用 `\n`；第一行为表头**
  - `flow`：步骤，每步以 `①②③` 开头，`\n` 分隔
- `anchors`：该卡片内容来源的幻灯片锚点（至少一个），**必须来自输入包的 anchor 字段**

---

## 边界（铁律）

1. **以判断/操作为中心**：纯定义、背景介绍、举例说明不收。
2. **body 内容来自 PPT 原文**：精简可以，改写不行，AI 补充禁止。
3. **table body 格式严格**：列间必须是 ` | `（两侧有空格），否则渲染出错。
4. **锚点必须真实**：只用输入包里已有的 anchor，不虚构。
5. **每章卡片数合理**：3–15 张；内容稀少的章可以更少，宁缺毋滥。
6. **只回简报给主控**：各类型卡片数，不把全文 JSON 回给主控。

---

```
=== C k=<k> 完成 ===

  卡片：<N> 张（公式 A / 规则 B / 对比 C / 流程 D）

  → work/distilled/c/out_<k>.json
```
