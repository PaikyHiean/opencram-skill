# M 子 agent（思维导图·每章）

**何时用**：Phase 10，思维导图管线（工作流默认）。orchestrator 按单章派一个 Task 子 agent，
每个只领一章的 `work/distilled/m/in_<k>.json`，控制上下文。

> 本 agent 产出 **4 层结构**（章 → L2 分支 → L3 子分支 → L4 叶节点）。
> `render_m.py` 依据 `branches` 中是否含 `subbranches` 自动选择 4 层渲染。

---

## 输入

子 agent 自己读盘（orchestrator 不传全文）：

```
work/distilled/m/in_<k>.json
```

格式：
```json
{
  "chapter_index": 1,
  "chapter_title": "第1章 财产保险概论",
  "section_count": 17,
  "sections": [
    {
      "label": "一、",
      "heading": "财产保险的概念与标的",
      "pointer": "源：第一章财产保险概论.ppt s.2–5",
      "points": ["以财产及有关利益为保险标的保险。", "有形财产（有实物形态）", "无形财产：责任、信用等"]
    }
  ]
}
```

---

## 任务

将该章所有小节归纳为 **4–6 个主题分支（L2）**，每个分支下 **2–3 个子分支（L3）**，
每个子分支下 **2–3 个叶节点（L4）**。

### 严格数量限制（铁律）

| 层级 | 标题/内容字数 | 每章数量上限 |
|---|---|---|
| L2 分支 | 4–8 字 | **4–6 个**（禁止超过 6） |
| L3 子分支 | 4–7 字 | 每个 L2 最多 **3 个**（不超过 3） |
| L4 叶节点 | 8–20 字 | 每个 L3 最多 **3 个**（不超过 3） |
| 全章叶节点 | — | **目标 30–54 个**（禁止超过 54） |

> 推算：6 L2 × 3 L3 × 3 L4 = 54（上限）；4 L2 × 2 L3 × 2 L4 = 16（下限）。
> 典型值：5 L2 × 2–3 L3 × 2–3 L4 ≈ 30–45 叶节点。

### 归纳原则

- 把内容相近的小节合并为一个 L2 分支（如"保险价值"+"保险金额" → "保险价值与金额"）
- L3 是 L2 内部的子主题群，应与 L2 标题有明确的层级关系
- L4 节点优先选：定义、条件、数字、分类名称、流程名称
- **所有 L4 内容来自 PPT 原文，可精简但禁止 AI 补充**
- 宁可节点少而精，不要为凑数量而拆过细

---

## 边界（铁律）

1. **节点来自原文**：只精简，不补充 AI 内容
2. **数量上限不可突破**：L2 ≤6，每 L2 的 L3 ≤3，每 L3 的 L4 ≤3，全章 L4 ≤54
3. **宁少勿多**：超量时优先合并同主题，而不是拆分更细
4. **只回简报**：不把全文 JSON 回给主控
